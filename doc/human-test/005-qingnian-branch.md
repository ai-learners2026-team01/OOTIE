# OOTie 人工驗收指南：legacy/qingnian 功能整合 (首頁連結更新、通知與登入模組化、會員 Popover 選單與進場動畫統一)

> **文件版本**：1.0.0  
> **建立日期**：2026-09-26  
> **測試對象**：`legacy/qingnian` 分支（首頁連結更新、通知模組獨立拆分與未讀標記、登入/註冊 Modal 與會員 Popover 選單數據統計、頁面切換與卡片入場動畫統一）重構至 Vue 3 + Pinia + Vue Router 專案之功能驗收  
> **技術棧**：Vue 3 + Pinia + Vue Router + Vite + Supabase

## 🛠️ 1. 準備工作 (Prerequisites)

在進行人工驗收之前，請確保本地環境已安裝依賴並啟動開發伺服器。

```bash
# 1. 安裝套件（若尚未安裝）
npm install

# 2. 啟動 Vite 本機開發伺服器
npm run dev
```

啟動完成後，開啟瀏覽器瀏覽 `http://localhost:5173/`。

## 📋 2. 人工驗收項目與操作步驟

### 驗收項目 1：首頁連結與路由導向對齊 (`src/router/index.js`)

- **測試目標**：驗證全站導覽列與連結皆導向現代化 Vue Router 路由 `/`，舊有 `home.html` 或 `/home` 連結自動無縫重定向至首頁。
- **操作步驟**：
  1. 點擊頂部導覽列或側欄的「OOTie」品牌標誌。
  2. 觀察網址列導向 `/`，且頁面正確載入首頁 `HomeView.vue` 的情境穿搭推薦內容。
  3. 在瀏覽器網址列手動輸入 `http://localhost:5173/home` 並按下 Enter。
  4. 觀察系統自動重定向至 `http://localhost:5173/`，確定沒有任何 404 或死連結。
- **預期結果**：
  - 首頁連結統一為 `/`，網址重定向順暢。

---

### 驗收項目 2：通知模組、未讀標記與歷史資料遷移 (`AppTopbar.vue`, `NotificationModal.vue` & `app.js`)

- **測試目標**：驗證右上角通知按鈕提示、開啟自動清除未讀標記、深層連結導航，以及相容舊版 `ootie-notifications-v1` LocalStorage 資料遷移。
- **操作步驟**：
  1. 進入頁面，觀察右上角通知按鈕 `♧` 顯示紅點未讀數字 Badge（若有未讀通知）。
  2. 點擊 `♧` 按鈕開啟通知 Modal 視窗。
  3. 觀察未讀標記數字歸零且自動清除未讀狀態。
  4. 點擊通知項目中的帳號連結（如 `@ella`），驗證視窗關閉並自動導向 `/profile?user=@ella`。
  5. 點擊帶有貼文/求救細項的通知，驗證成功跳轉並開啟對應內容視窗。
  6. （測試歷史遷移）手動在瀏覽器 Console 執行 `localStorage.setItem('ootie-notifications-v1', JSON.stringify([{ id: 'test-1', text: '測試舊通知', time: '剛剛', read: false }]))` 並重新整理頁面，驗證新通知成功匯入與呈現。
- **預期結果**：
  - 通知顯示、未讀數統計與深層跳轉皆正常運作。
  - 舊版獨立 key `ootie-notifications-v1` 可被 Pinia `appStore` 自動識別與遷移。

---

### 驗收項目 3：會員登入 / 註冊 Modal 與舊版認證狀態相容 (`AuthModal.vue` & `auth.js`)

- **測試目標**：驗證未登入狀態點擊「登入 / 註冊」開啟 Modal 視窗，支援 Email/手機號碼 分頁切換與驗證提示，且相容舊版 `ootie-auth-state-v1`。
- **操作步驟**：
  1. 於登出狀態下點擊頂部導覽列右側的 **「登入 / 註冊」** 按鈕。
  2. 驗證成功彈出 `AuthModal` 視窗。
  3. 點擊「登入」與「註冊」分頁頁籤，觀察表單欄位根據選擇即時切換。
  4. 輸入帳密後提交，驗證登入成功並跳出 Toast 提示「登入成功！歡迎回來」。
  5. （測試歷史相容）若 LocalStorage 存有 `ootie-auth-state-v1: "true"`，系統初始化時能正確辨識已登入狀態。
- **預期結果**：
  - Modal 視窗切換流暢，表單驗證提示清楚，驗證狀態正確同步。

---

### 驗收項目 4：會員頭像 Popover 氣泡選單與數據統計 (`AppTopbar.vue`)

- **測試目標**：驗證已登入狀態下點擊頂部頭像彈出會員專屬選單，顯示個人數據（Hearts、幫助衣友、獲得讚數）與快捷跳轉/登出功能。
- **操作步驟**：
  1. 於已登入狀態下，點擊右上角會員頭像（顯示 Initial 或大頭照）。
  2. 觀察右側順暢彈出 `Profile Popover` 氣泡選單。
  3. 檢查選單內顯示內容：
     - 使用者大頭貼 / Initials
     - 姓名（如 `Hayley Lin`）與帳號 Handle（如 `@hayley`）
     - 三項統計數據：**Hearts**（點讚數）、**幫助衣友**（SOS 建議數）、**獲得讚數**
  4. 點擊選單中的 **「前往個人檔案」** 按鈕，驗證自動導向 `/profile` 頁面並收合選單。
  5. 再次開啟選單點擊 **「登出」** 按鈕，驗證成功登出並跳出 Toast「已登出」，頂部按鈕還原為「登入 / 註冊」。
  6. 測試點擊選單外部遮罩或 `×` 按鈕可關閉 Popover 選單。
- **預期結果**：
  - 會員 Popover 數據正確顯示，選單開合流暢，跳轉與登出功能健全。

---

### 驗收項目 5：頁面切換與列表卡片進場動畫統一 (`src/assets/main.css`)

- **測試目標**：驗證移除舊版卡片列表的延遲進場動畫 (`animation: rise`)，實現頁面導航與單品/社群牆的即時直接渲染。
- **操作步驟**：
  1. 點擊導覽列在「首頁」、「數位衣櫥」、「OOTD 探索」、「Style SOS」、「個人檔案」之間快速切換。
  2. 觀察頁面內容切換瞬間直接呈現，不再等待舊頁淡出或新頁上滑動畫。
  3. 在「數位衣櫥」頁面點擊分類標籤（如「上衣」、「下身」、「鞋履」）。
  4. 觀察過濾後的單品卡片 (`.item-card`) 即時更新展示，沒有漸進式延遲進場卡頓感。
  5. 瀏覽「OOTD 探索」牆 (`.ootd-card`) 與「Style SOS」牆 (`.sos-feed-card`)，確認卡片載入快速清晰。
- **預期結果**：
  - 頁面與列表卡片完全去除沉重的進場動畫，操作體驗極致順暢。
