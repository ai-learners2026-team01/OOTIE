## 🛠️ 1. 準備工作 (Prerequisites)

在進行人工驗收之前，請確保本地環境已準備好 Supabase 設定與開發伺服器。

```bash
# 1. 複製 .env 範例檔並填入實際 Supabase 金鑰（若已有 .env 可跳過複製）
cp .env.example .env

# 在 .env 檔案中確認填入：
# VITE_SUPABASE_URL=https://your-project.supabase.co
# VITE_SUPABASE_ANON_KEY=your-actual-anon-key

# 2. 安裝套件（若尚未安裝）
npm install

# 3. 啟動 Vite 本機開發伺服器
npm run dev
```

啟動完成後，在瀏覽器中開啟本機網址（預設為 `http://localhost:5173/`），並點擊側邊欄進入 **「Style SOS / 穿搭求救」** 頁面。

## 📋 2. 人工驗收項目與操作步驟

### 驗收項目 1：穿搭求救頁籤切換與搜尋 (Style SOS Tabs & Search)

- **測試目標**：驗證「衣友求救板」與「我發出的求救」雙頁籤可流暢切換，且關鍵字搜尋能即時過濾求救貼文。
- **操作步驟**：
  1. 進入 `/sos` 頁面，預設位於 **「衣友求救板 (Received)」** 頁籤。
  2. 觀察頁籤上顯示之數量標籤（例如：`衣友求救板 (3)`）。
  3. 點擊 **「我發出的求救 (Sent)」** 頁籤，切換至使用者自己發布的求救列表。
  4. 在頂部搜尋列輸入關鍵字（例如：`約會` 或 `面試`）。
- **預期結果**：
  - 頁籤切換時底部指示線與文字樣式流暢變換，貼文列表即時更新。
  - 「衣友求救板」僅顯示其他衣友進行中的求救 (OPEN)。
  - 「我發出的求救」顯示使用者個人歷史發布之求救（包含 OPEN 與 CLOSED 狀態卡片）。
  - 搜尋列能精準過濾符合標題、場合、天氣或風格標籤之貼文。

---

### 驗收項目 2：發布穿搭求救與公開衣物選取 (Create SOS & Public Closet Picker)

- **測試目標**：驗證發布求救時可設定標題、細節、場合、天氣、風格，並能明確勾選本次願意公開給衣友的衣物單品（`closet_item_ids` 隱私控制）。
- **操作步驟**：
  1. 點擊頂部 **「＋ 發布求救」** 按鈕開啟彈窗。
  2. 輸入標題（例如：`週末露營穿搭求救`）與詳細說明。
  3. 選擇場合（戶外活動）、天氣（微涼有風）、穿著時機（週末）與風格標籤（Relaxed）。
  4. 捲動至 **「本次公開給衣友的衣物」** 區塊：
     - 點擊「取消全選」，確認選擇計數變為 `已選 0 件` 並出現警示文字 `請至少選擇 1 件要公開給衣友的衣物。`
     - 點擊「全選」或手動勾選 2~3 件個人衣單品。
  5. 點擊 **「發布求救」**。
- **預期結果**：
  - 未勾選任何衣物時無法送出，並會彈出 Toast 提示。
  - 勾選衣物並送出後，彈窗關閉，跳出 Toast 提示：`穿搭求救已發布`。
  - 切換至「我發出的求救」頁籤，可看到剛發布的卡片，卡片下方顯示公開單品縮圖與 `OPEN` 狀態標籤。

---

### 驗收項目 3：為衣友提供搭配建議與公開衣物邊界驗證 (Submit Suggestion & Shared Closet Constraint)

- **測試目標**：驗證衣友只能使用求救貼文主動公開的衣物進行搭配，且具備「不允許為自己求救貼文提交建議」之機制 (`Self-Suggestion Guard`)。
- **操作步驟**：
  1. 在「衣友求救板」選擇一張其他人發布的 OPEN 求救卡片，點擊 **「幫她搭配」**。
  2. 在彈出的搭配建議視窗中，確認單品選取區塊：
     - **僅顯示該筆求救貼文公開的單品**，絕不洩漏該使用者未公開的其他衣櫥內容。
  3. 勾選 1~2 件單品，觀察上方「目前搭配」預覽區呈現組裝照片與單品名稱組合。
  4. 輸入給她的建議說明文字，點擊 **「送出建議」**。
  5. （防呆測試）若嘗試在自己的求救卡片上點擊搭配，系統阻擋並提示：`你不能為自己的求救貼文提交搭配建議。`
- **預期結果**：
  - 單品選取範圍嚴格限制在發布者公開的 `closet_item_ids` 內。
  - 搭配預覽即時更新。
  - 成功送出後彈出 Toast：`穿搭建議已送出，謝謝你的搭配`，個人檔案 helped 計數 +1。

---

### 驗收項目 4：SOS 詳情彈窗、點讚與採納搭配 (SOS Detail, Like & Adopt)

- **測試目標**：驗證點擊詳情可展開完整 SOS 圖庫與回覆列表，並支援「點讚」與發布者「採納搭配（Adopt）」。
- **操作步驟**：
  1. 在任意求救卡片上點擊 **「查看詳情」** 開啟詳情彈窗。
  2. 檢視求救完整敘述、公開衣物圖庫列表、Helper 人數統計與已收到的搭配建議卡片。
  3. 點擊建議卡片右下角的 **「♡ 喜歡」**。
  4. 若使用者為該求救貼文之發布者，點擊某張建議卡片上的 **「採用搭配」**。
  5. 再次點擊「採用搭配」確認可取消採納。
- **預期結果**：
  - 點擊喜歡變更為 `♥ 已喜歡`（字體變紅醒目）。
  - 點擊「採用搭配」後，該張建議卡片上方出現 `★ 發布者已採納` 綠色標籤。
  - **重要業務規則驗證**：採納建議後 **SOS 狀態仍保持 `OPEN`**，不會自動關閉求救。

---

### 5. 驗收項目 5：結束求救生命週期 (Explicit SOS Close Lifecycle)

- **測試目標**：驗證只有明確執行「結束這次求救」才會將狀態由 `OPEN` 轉為 `CLOSED`，且 CLOSED 貼文不再出現在衣友求救板。
- **操作步驟**：
  1. 在發布者自己的 OPEN 求救貼文（在「我發出的求救」頁籤或詳情彈窗中），點擊 **「結束求救」** 或 **「結束這次求救」**。
  2. 出現二次確認彈窗：`結束這次求救？結束後將不再接受新的搭配建議...`。
  3. 點擊 **「確認結束」**。
- **預期結果**：
  - 該筆求救狀態標籤由 `OPEN` 變更為灰底 `CLOSED`。
  - 切換至「衣友求救板 (Received)」，該筆貼文已不再顯示。
  - 切換至「我發出的求救 (Sent)」，該筆貼文仍完好保留於歷史紀錄中供後續查閱。
