# OOTie 人工驗收指南：legacy/Hayley 功能整合 (側欄收合、天氣動態推薦、追蹤系統、深層連結通知與手機版 Quick Action)

> **文件版本**：1.0.0  
> **建立日期**：2026-09-26  
> **測試對象**：`legacy/Hayley` 分支（側欄收合記憶、Open-Meteo 天氣 API 穿搭推薦與 Reroll、追蹤/取消追蹤與關注 Feed、通知深層連結 Deep Link、手機版 Quick Action ＋ 跨頁 `?quick=` 開啟 Modal）重構至 Vue 3 + Pinia + Vue Router 專案之功能驗收  
> **技術棧**：Vue 3 + Pinia + Vue Router + Vite + Open-Meteo API

## 🛠️ 1. 準備工作 (Prerequisites)

在進行人工驗收之前，請確保本地環境已啟動開發伺服器。

```bash
# 1. 安裝套件（若尚未安裝）
npm install

# 2. 啟動 Vite 本機開發伺服器
npm run dev
```

啟動完成後，開啟瀏覽器瀏覽 `http://localhost:5173/`。

## 📋 2. 人工驗收項目與操作步驟

### 驗收項目 1：側欄收合 / 展開與狀態持久化 (`AppSidebar.vue`)

- **測試目標**：驗證桌機版側欄收合按鈕可順暢切換完整與精簡圖示模式，並在重新整理瀏覽器後保持偏好狀態。
- **操作步驟**：
  1. 開啟桌機版網站（螢幕寬度 > 900px），觀察左側側欄預設為展開狀態（包含品牌標誌 `OOTie` 與完整選單文字）。
  2. 點擊品牌右側的收合按鈕 `❮`。
  3. 觀察側欄寬度自動縮減為 78px 精簡圖示模式（隱藏 `OOTie` 字樣與選單文字，僅保留圖示）。
  4. 重新整理頁面（F5 / Cmd+R），確認側欄仍保持收合狀態（驗證 `localStorage['ootie-sidebar-collapsed']` 持久化成功）。
  5. 點擊展開按鈕 `❯`，側欄順暢展開還原。
- **預期結果**：
  - 側欄收合／展開動畫流暢。
  - 收合狀態在重新整理或切換頁面後維持不變。

---

### 驗收項目 2：即時天氣模組、場合加權推薦與重新搭配 (Reroll) (`HomeView.vue`)

- **測試目標**：驗證首頁調用 Open-Meteo 氣溫與天氣加權挑選衣櫥單品、支援點擊衣服看詳細資訊與 Reroll 避開當前單品。
- **操作步驟**：
  1. 進入首頁 `/`，觀察右上角顯示當前天氣標籤與氣溫圖示（如 `🌤️ 23°C 台北` 或 Open-Meteo 即時資料）。
  2. 點擊「上班」、「約會」、「旅行」、「隨性」、「聚會」、「正式」、「運動」7 種場合按鈕。
  3. 觀察「OOTie 為你挑了一套」推薦區塊標題、文案與 3 件推薦單品卡片即時更換。
  4. 點擊推薦區塊內的任一衣服單品，驗證成功開啟 `ItemDetailModal` 並顯示單品詳細資訊（品牌、風格、季節、穿著次數等）。
  5. 點擊推薦區塊右上角的 **「↻ 重新搭配」** 按鈕，驗證系統自動避開畫面上現有的單品，挑選出一套全新的組合。
  6. 點擊「OOTD Inspiration」靈感卡片，驗證自動跳轉至探索頁並開啟該貼文詳情。
- **預期結果**：
  - 天氣資訊成功獲取並作為 `weatherScore()` 評分權重。
  - 場合切換與 Reroll 邏輯正確運作，點擊衣服可看明細。

---

### 驗收項目 3：追蹤系統 (Follow System) 與「追蹤中」 Feed 篩選 (`ExploreView.vue` & `ProfileView.vue`)

- **測試目標**：驗證在個人檔案頁進行追蹤／取消追蹤，狀態可同步至全域與探索頁「追蹤中」動態牆。
- **操作步驟**：
  1. 進入 `/explore` 探索頁，點擊貼文作者名稱 `@sofia` 或頭像，自動跳轉至 `/profile?user=@sofia`。
  2. 觀察他人個人檔案頂部顯示 **「← 返回探索」** 連結與 **「＋ 追蹤」** 按鈕。
  3. 點擊「＋ 追蹤」，按鈕變更為「已追蹤」（Secondary 樣式），並顯示 Toast 提示「已開始追蹤 @sofia」。
  4. 點擊「← 返回探索」回到探索頁，切換頁籤至 **「追蹤中」**。
  5. 驗證 `@sofia` 的貼文已出現在「追蹤中」Feed。
  6. 再次進入其檔案頁點擊「已追蹤」取消追蹤，回到探索頁「追蹤中」確認該貼文已即時移除。
- **預期結果**：
  - 追蹤狀態全域同步更新（`appStore.followingUsers`）。
  - 探索頁「追蹤中」頁籤動態篩選符合預期。

---

### 驗收項目 4：通知系統與細項深層連結 (Deep Link Notification) (`NotificationModal.vue`)

- **測試目標**：驗證開啟通知視窗自動標記已讀，點擊通知中的帳號字樣跳轉至個人檔案，點擊整條通知深層跳轉至指定貼文/留言/求救。
- **操作步驟**：
  1. 點擊頂部導覽列的「通知鈴」圖示開啟通知 Modal，驗證未讀標記自動清除。
  2. 點擊通知項目中的 **`@ella`** 帳號字樣（如 `@ella 喜歡了你的穿搭` 中的 `@ella`）。
  3. 驗證視窗關閉並自動導向 `/profile?user=@ella`。
  4. 再次開啟通知視窗，點擊整條帶有留言深層連結的通知（如 `@minji 回覆了你的留言`）。
  5. 驗證系統自動跳轉至 `/explore?post=post-01&comment=comment-03` 並開啟貼文留言視窗。
- **預期結果**：
  - 點擊帳號文字與點擊整條通知具備正確的分流目的地。
  - 深層連結傳遞與目標 Modal 開啟流暢。

---

### 驗收項目 5：手機版 Quick Action 浮動膠囊選單與跨頁 `?quick=` 跳轉 (`AppBottomNav.vue`)

- **測試目標**：驗證手機版底部導覽中間「＋」按鈕彈出浮動選單，且支援本頁直接開啟或跨頁 `?quick=` 帶參數開啟 Modal。
- **操作步驟**：
  1. 切換瀏覽器至手機模擬檢視模式（寬度 <= 760px）。
  2. 觀察底部導覽列中間顯示黑色圓形「＋」按鈕。
  3. 點擊「＋」，觀察彈出懸浮 Quick Action 選單（包含「加入單品」、「發布 OOTD」、「發布求救」三選項）。
  4. 在 `/home` 頁面點擊選單中的 **「發布 OOTD」**。
  5. 觀察網址導向 `/explore?quick=add-ootd`，且頁面載入後自動開啟發布 OOTD 表單 Modal。
  6. 切換至 `/closet` 點擊 **「加入單品」**，驗證在同頁直接開啟 ItemFormModal 表單。
- **預期結果**：
  - 浮動選單動畫自然，點擊遮罩可關閉選單。
  - 跨頁帶 `?quick=` 參數能準確觸發開啟對應表單 Modal。
